Zebra Onboarding

This is a personal onboarding course for Zebra, the Rust implementation of a Zcash full node maintained by the Zcash Foundation. The course is the kind of document that I, the reader, would have wanted when I first opened the repo, in the order I would have wanted to read it.

The audience is one person (me, the maintainer of this fork). It is written in the second person because that turned out to be the clearest voice, not because it is meant to teach anyone in particular.

Notation​

The course reuses the same notation across chapters. Once is enough.

  • Fp\mathbb{F}_pFp​: a prime field of order ppp. For Zcash, ppp is the base field of either Jubjub (Sapling), Pallas (Orchard), or BLS12-381 (Groth16).
  • G\mathbb{G}G: a cyclic group of prime order qqq, written additively.
  • [k]P[k]P[k]P: scalar multiplication of point P∈GP \in \mathbb{G}P∈G by scalar k∈Fqk \in \mathbb{F}_qk∈Fq​.
  • Hℓ(⋅)H_\ell(\cdot)Hℓ​(⋅): a hash with ℓ\ellℓ-bit output (Blake2b for most KDF/PRF paths, Pedersen for fixed-domain commitments, Sinsemilla for the Orchard tree, Poseidon for in-circuit).
  • e(⋅,⋅)e(\cdot, \cdot)e(⋅,⋅): the BLS12-381 pairing G1×G2→GT\mathbb{G}_1 \times \mathbb{G}_2 \to \mathbb{G}_TG1​×G2​→GT​, used by Groth16.
  • Com(m;r)\mathsf{Com}(m; r)Com(m;r): a commitment to message mmm with randomness rrr. In Sapling, Com\mathsf{Com}Com is a Pedersen commitment; in Orchard, the value commitment uses Pallas and the note commitment uses Sinsemilla.
  • Enck\mathsf{Enc}_kEnck​ / Deck\mathsf{Dec}_kDeck​: symmetric encryption (ChaCha20-Poly1305 in Sapling note encryption).
  • \stackrel{\}{\leftarrow}$: uniform random sampling.
  • a∣ba \mathbin{\\|} ba∣b: byte-string concatenation.

How to Read This Course​

The chapters are ordered as the dependency graph of the codebase: you cannot understand chapter nnn without chapters 111 through n−1n-1n−1. The two load-bearing chapters are:

  1. Workspace, Dependency Graph, and Build - the crate map and the build commands you will run every day.
  2. Testing, Build, and CI - what every PR must pass locally before it goes anywhere.

The last chapter, First 90 Days, is a reading and contribution plan that converges on a real PR.

Contribution Gate (Read Before Opening a PR)​

The upstream CLAUDE.md enforces a contribution gate: no PR before issue discussion with a Zcash Foundation team member. The detail is in chapter 22 and in the upstream CLAUDE.md. Skipping it gets the PR closed regardless of how good the code is.
